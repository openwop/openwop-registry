## Authoring checklist

This source tree was generated by `scripts/new-pack.mjs` from the registry's
`templates/node-pack/`. It is already a v2 manifest
([`spec/v2/core/packs.md`](https://github.com/openwop/openwop/blob/main/spec/v2/core/packs.md)).
Keep it that way while you edit:

- **`kind`** stays. v2 has no "absent means node" reading.
- **`engines.openwop`** keeps an explicit ceiling that admits major 2
  (`>=1.0.0 <3.0.0`). A range without one is refused by a v2 host.
- **`peerDependencies`**: add one key per host service your nodes read through
  `ctx.*`. Keys are capability family keys from
  [`spec/v2/declaration.json`](https://github.com/openwop/openwop/blob/main/spec/v2/declaration.json)
  (`aiEnvelope`, `secrets`, `aiProviders`, ...), never dotted v1 keys such as
  `host.aiEnvelope`. Name facets, and mark a dependency optional, in
  `peerDependenciesMeta`:

  ```json
  "peerDependencies": { "secrets": "required" },
  "peerDependenciesMeta": { "secrets": { "facets": ["resolveInPack"] } }
  ```

- **No `signing` block.** The build step writes
  `{ "keyId": "...", "scheme": "ed25519-canonical-json" }` for you.
- **Schema `$id`s** are `https://packs.openwop.dev/{NAME}/<version>/<file>`.
  When you bump `version`, bump every `$id` in `schemas/` with it.

## Build, stage and verify

From the registry clone root, with your key registered in
`registry/.well-known/openwop-registry.json` `signingKeys[]` (see the
[pack author quickstart](https://github.com/openwop/openwop/blob/main/docs/PACK-AUTHOR-QUICKSTART.md)):

```bash
node scripts/build-pack-tarball.mjs --pack {NAME} \
  --signed --key ~/.openwop-keys/<keyId>.private.pem --key-id <keyId> \
  --tree v2 --scheme ed25519-canonical-json
node scripts/auto-register.mjs --tree v2 \
  --key-file ~/.openwop-keys/<keyId>.private.pem --key-id <keyId> \
  --scheme ed25519-canonical-json
node registry/scripts/verify-signatures.mjs --tree v2
npm run check
```
